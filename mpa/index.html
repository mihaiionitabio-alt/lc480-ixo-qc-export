Help, methods and instructions

Quick start

  1. Drop your finished .ixo files, or a ZIP containing them, onto the load area.
  2. Pick the preset that matches your assay. Absolute quantification is the default and suits most runs.
  3. Press Analyze.
  4. Read Summary for the numbers and Runs and QC for the acceptance decision. The tab bar only shows the sheets your experiment actually has data for; press More sheets for the rest.
  5. Press Build evidence report, then Print / save as PDF or Download evidence bundle.

Nothing is uploaded and nothing is recalculated that the instrument already stored. Crossing points, calls, melting temperatures, genotypes and ratios are reproduced exactly as saved.

Loading files

Drop individual .ixo files or a .zip archive containing them. ZIP entries are checked against their stored size and CRC-32 before anything is read, so a truncated or corrupted archive is refused rather than silently half-decoded. RAR is not supported. Each source file is named with its size in the evidence report.

One plate is enough for everything except the multiple-plate comparison sheets and the control charts, which need at least two runs to be meaningful. Plate geometry is read from the block type the instrument recorded, so 96-well and 384-well runs are both handled without being told which is which.

What Analyze does

Pressing Analyze runs the whole pipeline in your browser. Each file is opened as an XML object stream; the deflate-compressed acquisition store is inflated to recover the per-cycle fluorescence; the plate model is read to recover sample names, identifiers, notes, subsets, replicate groups, target names, declared concentrations and the instrument's sample-type assignment; and every analysis object the experiment carries is read for its stored results, whichever module produced them.

Wells are then classified into roles, checked against the acceptance rules, reduced to replicate statistics, assembled into a study across plates, and turned into standard curves, calls, control charts and a forensic timeline.

Stored results are never re-estimated. Where this page computes something the instrument did not store — the refitted standard curve, the efficiency index, the multiple-plate statistics, the sample calls, the control-chart limits — the report says so explicitly and records the options used.

The analysis modules

The LightCycler 480 software family stores several kinds of analysis inside one experiment file, and this page reads all of them. What appears on screen depends on what your experiment contains.

Absolute quantification converts a crossing point into a concentration using a standard curve. Both crossing-point methods are handled: the second-derivative maximum, which needs no user input and no baseline correction, and fit points. The stored crossing point is the number this page reports; the method that produced it is named on the Overview sheet.

Relative quantification compares the ratio of a target to a reference in a sample against the same ratio in a calibrator, and reports the result as a normalised ratio. Where the file carries stored result sets, they appear on the Relative quantification sheet with their crossing-point medians, concentration ratios and normalised ratios. Where it does not, the same comparison can be computed here from the crossing points on the Sample calls sheet.

Tm calling reports, for each sample, the melting temperature and the area, height and width of each melting peak. These appear on the Melting sheet.

Endpoint genotyping, melting-curve genotyping and gene scanning all produce a genotype call per well, with a score and group name where the module records them. These appear on the Genotyping sheet. Hardy-Weinberg is calculated only after the result groups can be assigned unambiguously to AA, AB and BB; arbitrary scanning groups remain unassigned rather than being guessed.

Color compensation objects are recognised and reported, and each well's dominant channel is shown on the per-well sheet. The compensation itself is not applied to the fluorescence: curves are drawn as stored.

Presets, and reading the settings from the file

Read the settings from the file is the default and is what you want for a finished experiment. A processed .ixo already records what was measured and how, so nothing needs to be chosen: the analysis modules, the detection channels and their names, the plate geometry, the sample type of every well, the replicate grouping, which targets are targets and which are endogenous references, and whether standards with concentrations were run. All of it is read from the container and listed on screen with the field each value came from, so you can see what was assumed and correct it.

Two consequences worth knowing. Acceptance rules are emitted only for the control roles actually present on the plate — a required rule for a control the operator never intended to run would fail the plate for the absence of something that was never there. And the sample-call layer switches itself on only when the file declares a target and a reference; on a plain quantification run it stays off.

The presets below are for the cases where the file does not say enough, or where you want to impose a laboratory SOP rather than follow the file. A preset sets the whole profile in one click. Editing anything in Advanced settings switches the preset to Custom; picking a preset again overwrites your edits.

Absolute quantification is the default. Controls must stay clean where they are meant to be clean, positive controls and calibrators must amplify within a broad window, standard curves are refitted from any standards on the plate, and no sample calls are issued.

Relative quantification adds a starting pattern that treats a target named like a housekeeping gene as the endogenous reference and everything else as a gene of interest, and switches the ΔCq call metric on. Edit both patterns to match your own target names.

Genotyping and Tm calling relaxes the quantification rules, keeps the no-template control requirement, and turns the efficiency estimator off, because it has nothing to work on in a melt-only experiment.

GMO screening is a worked example rather than a general mode: it encodes one laboratory's screening SOP, with the limit-of-detection control amplifying between Cq 29 and 36 for the transgenic elements, the endogenous taxon reference between Cq 20 and 27, no amplification in the blanks or the no-template control, and detection calls against the calibrator. It is included because it shows how a real acceptance framework maps onto these controls; adapt it or ignore it.

Raw decode only turns off every acceptance rule, grouping rule and call pattern, and disables the efficiency estimator and the curve refit. You get the decoded data, the plate map, the curves and the instrument records, with no interpretation layered on top. Use it when you want to inspect a file rather than judge it.

Study definition

A study is several experiments compared together, which is what the vendor Multiple Plate Analysis Software is for. A single plate works perfectly well; the study layer simply collapses to one column set.

Study column key decides what becomes a column. Keying by subset name merges the same assay across plates into one column and is what you want for a campaign. Keying by analysis name keeps every analysis object separate, which is what you want when one target was analysed twice with different settings or by two different crossing-point methods.

Unique sample names decides what becomes a row. Leave it on if the same sample name means the same sample on every plate; that is what makes a cross-plate comparison possible. Turn it off if plates were named independently, in which case the experiment name stays part of the row identity, exactly as in the vendor software.

Plate geometry is read from the block type recorded in the file and only needs overriding if a run was saved with an unexpected block.

Analysis options

AbsQuant result chooses what the study sheets display: the stored crossing point, the stored concentration, or the efficiency index computed from the raw curves.

AbsQuant statistics reduces each sample's replicates either to mean and standard deviation or to median and range, matching the vendor option. The standard deviation uses the n−1 denominator and no error propagation is applied, again following the vendor implementation.

Non-detected handling decides what happens to a well that did not amplify. Excluding it is the safe default for descriptive statistics. Substituting a fixed Cq makes every sample comparable at the cost of pulling means towards that value; the choice is recorded in the report either way.

Replicate source decides which wells are replicates of each other. The instrument's own Replicate of assignment is the most reliable, because it was made at plate setup and the file records it explicitly. The regex option splits a trailing letter suffix off the sample name; the third option treats identical names as replicates.

Role source decides what each well is. The sample type recorded in the Sample Editor says whether a reaction was set up as an unknown, a standard, a calibrator or a control — an assignment independent of whatever the sample was called. The default uses that assignment for the broad family and lets your name rules refine it, because the file does not distinguish a no-template control from an extraction blank while a name rule can. Whichever option you choose, every disagreement between the two is listed on the Runs sheet: a disagreement means the plate layout and the naming convention diverged, which is worth knowing.

t-test variant selects paired, equal-variance or Welch. Paired is the default because the same samples are normally measured for every target on a plate. The vendor documentation does not fix a variant, so the choice is yours and is recorded.

Standard curves

In an absolute quantification the concentrations of the standards are plotted against their crossing points: the x axis is the logarithm of the initial target concentration and the y axis is the crossing point in cycles. The slope of that line is the amplification efficiency, because a perfect reaction doubles the target every cycle; the manual gives the conversion as E = 10-1/slope, so a perfect reaction has an efficiency of 2 and real reactions usually sit a little below it.

This sheet shows two curves side by side. The stored curve is what the instrument saved: its fit method, curve type, validity state, slope, intercept, efficiency and error. The refit curve is computed here from the standards actually present on the plate — wells whose sample type is Standard and whose concentration was entered in the Sample Editor — and reports slope, intercept, coefficient of determination, mean squared error and efficiency. The manual treats a mean squared error below 0.2 as acceptable, and the sheet flags anything above it.

A run whose stored curve has no standards attached and a slope of zero was quantified against an assumed efficiency rather than a fitted calibration. Its concentrations are relative values, and both this sheet and the forensic log say so rather than presenting them as absolute copy numbers.

The manual recommends at least five serially diluted standards spanning the expected range of the target, and notes that an external standard curve saved from an earlier run is only valid if the detection format, analysis mode and colour compensation match.

Relative quantification

A relative quantification compares two ratios: the target to the reference in an unknown sample, and the same two sequences in a calibrator. The result is the normalised ratio, the first divided by the second. The reference is a sequence present at constant copy number in every sample, which normalises sample-to-sample differences; the calibrator is a stable positive sample that both normalises within a run and gives a constant calibration point between runs.

Because the comparison is a function only of efficiency and the crossing points, it needs no standard curve in each run and does not determine absolute copy numbers. Its prerequisites are that the efficiencies of standards and unknowns are identical, that target and reference efficiencies do not vary between samples, and that the reference gene is not regulated in the system under study.

A calibrator corrects for differences in detection sensitivity between target and reference — probe annealing, energy transfer efficiency, dye extinction — but it does not correct for a difference in PCR efficiency between the two genes. That is what efficiency correction is for, and setting both efficiencies to 2 gives only an approximation.

Where the file carries stored result sets, this sheet lists them with their crossing-point medians and standard deviations, the concentration ratio, the normalised ratio, and the correction and multiplication factors applied. Where it does not, set a called-target and reference pattern on the Sample calls sheet and the ΔCq and 2-ΔΔCq columns give the same comparison computed from the crossing points.

Melting curves and Tm calling

During a melt program the fluorescence of each sample is followed while the temperature rises. The melting temperature is the point at which half the double-stranded product has separated, or half the probes have melted off their target, depending on the detection chemistry. Plotting the negative first derivative turns that transition into a peak, which makes small differences between samples easy to see.

The Tm calling module records, for each sample, the melting temperature of every peak together with the area, height and width of the peak, and any shoulder temperatures. This sheet reports those values as stored, with a histogram of the first melting temperature by target.

Two practical notes from the manual: the automatic algorithm needs the melt program to start at least 7 °C below and end at least 3 °C above the expected melting temperature, and after a hydrolysis-probe PCR all probes are digested, so no melting analysis is possible.

Sample grouping

Grouping lets you ask whether a property of the sample changes the result. Define a property name, a value, and a regular expression matched against the sample name. Rules are evaluated in order and the first match assigns the value, so put specific patterns above general ones. A sample matching no rule for a given property shows as [not assigned].

Once at least one property exists and grouping is applied, the grouping columns appear in the Summary and Trend sheets, the filter bar becomes available on every sheet, and the Criteria Comparison sheet activates.

The vendor manual suggests naming samples so that the group is already part of the name — and warns against names made only of digits, which sort alphabetically rather than numerically. Both pieces of advice make grouping here easier too.

Acceptance rules

Classification rules decide what each well is. Acceptance rules decide whether it passed. Write the classification patterns first, then one acceptance rule per role and target family.

Expectation must amplify checks that the stored call is positive and the stored crossing point falls inside the interval. Expectation must stay clean checks that nothing amplified. Mark a rule required when its absence should fail the plate — a plate with no no-template control is not a passing plate, and treating a missing control as silently acceptable is the failure mode this flag exists to prevent.

Replicate spread is checked separately: replicates that all amplify must fall within the configured number of cycles, replicates that all fail to amplify pass as consistently non-detected, and a mixed group is reported as discordant.

The roles offered follow the vocabulary of the Sample Editor and the relative quantification module: unknown, standard, calibrator, positive and negative control, no-template control, blank, endogenous reference and internal control.

Sample calls

This is an optional decision layer, off until you give it a pattern. It answers the question "given the controls on this plate, what should I say about this sample?" for any assay where a calibrator defines the decision point.

For every sample and called target the replicate crossing points are reduced to a mean, with non-amplifying replicates counted at the configured substitute value. The sample is called at or above the calibrator if its metric is at least as strong, below the calibrator if it amplifies more weakly, and not detected if it does not amplify at all.

The Direct-Cq method compares the target mean crossing point itself. It is simple and robust but assumes comparable input material across wells. The ΔCq method subtracts the sample's own endogenous reference first, which cancels sample-to-sample differences in template amount, and the relative level 2-ΔΔCq expresses the result against the calibrator. A ΔCq comparison is only as trustworthy as the stability of the gene it normalises to, which is what the control charts are for.

If you set a reference pattern, the reference gates the whole call: a sample whose reference falls outside its acceptance window is reported as a reference failure, not as a negative, so that a false negative caused by a poor extraction cannot be mistaken for a true absence. Leave the reference pattern empty and the gate is simply not applied.

In a screening laboratory this is the layer that turns a crossing point into the sentence the laboratory issues, which is why the labels are configurable: the GMO preset renames the three outcomes to detected, below the limit of detection, and not detected.

Control charts

Each run contributes one point per charted control and target, ordered chronologically. The centre line and the one, two and three standard-deviation limits are computed across the loaded runs or supplied manually. The series is flagged with the usual multirules: a single point beyond three standard deviations, two consecutive points beyond two on the same side, a range of four standard deviations between consecutive points, four consecutive points beyond one on the same side, and ten consecutive points on one side of the centre line.

Charted against an endogenous reference, the same series doubles as an inhibition monitor. A sample whose reference crossing point drifts late relative to the established band, or whose efficiency index falls, is showing the kinetic signature of inhibition and belongs in a confirmatory dilution test.

Efficiency index

The file stores a crossing point per well but no per-well amplification efficiency. The window-of-linearity estimator recovers one from the raw curve: it scans candidate baselines, fits a straight line to the log-transformed, baseline-corrected fluorescence over the longest run of consecutive cycles inside the early exponential band, and keeps the fit with the highest coefficient of determination.

It is reported as a relative index rather than a calibrated efficiency, because a single-curve estimate is sensitive to baseline treatment. Where standards are present, the standard-curve efficiency on the Standard curves sheet is the calibrated quantity and should be preferred; the per-well index is for ranking reactions within a run and for spotting the ones that behave differently. A depressed index on an otherwise normal reaction is a flag, not a diagnosis.

Forensic audit

Creation, start, end and last-modified timestamps are compared to distinguish an untouched run from one edited after acquisition. Operator changes between creation and last save are reported, analyses created before the run ended or left in a non-final calculation state are flagged, and the stored result flags — uncertain crossing points, non-default crossing-point states, excluded wells, manual overrides, and any disagreement between a stored call and a stored crossing point — are counted and shown.

All instrument timestamps are wall-clock values as stored. The format does not encode a UTC offset, so no timezone conversion is applied and the report says so rather than implying a precision the data does not have.

Reading the sheets

The tab bar shows the sheets your experiment has data for; press More sheets for the full set, including the vendor multiple-plate comparison sheets. As a rule: Summary is the ground truth and ignores filters; Standard curves tells you whether the quantification is calibrated; Box Plot and T-Test answer whether two assays behave alike across the study; Criteria Comparison answers whether a grouping property changes a result; Trend and Statistics answer whether something is drifting along an ordered axis; Control charts answer whether the process was in control; Sample calls answers what each sample is.

If the Runs sheet shows a plate as failing acceptance, treat every number from that plate as provisional. The vendor software will happily compute statistics on a plate whose controls failed, and so will this one, because suppressing the numbers would hide the evidence.

Overview

Study metadata and every experiment and analysis included, with the columns the vendor Overview sheet lists — experiment, instrument, block size, analysis name, type, filter combination and timestamps — plus the thermal protocol, standard-curve state and the experiment/analysis Notes stored by the LightCycler software. Those notes often preserve the assay purpose, exact method settings or intended interpretation of an analysis.

Summary

Every sample with its grouping criteria and the per-analysis statistic. The instrument columns show the stored replicate statistics next to the recomputed values. They appear only where exactly one plate contributed to the cell, because the instrument computes them per plate; a sample measured on several plates has no single stored value to compare against.

Analysis Box Plot

Mean, standard deviation, median, minimum, maximum and the 25th and 75th percentiles over the per-sample means of each analysis. Percentiles use the inclusive linear-interpolation definition of the spreadsheet function the vendor software calls, so the numbers are directly comparable. Whiskers are drawn to the extremes rather than to a multiple of the interquartile range, matching the vendor graph.

Analysis T-Test

Every pair of analyses compared, two-tailed, sorted by p-value descending. The p-value comes from the regularised incomplete beta function, so no lookup table or approximation is involved.

Analysis Comparison

The value distribution of up to four analyses as an overlaid histogram, with the per-sample bars beneath it.

Criteria Comparison

Samples grouped by one property, with mean and standard deviation for each value of that property against each analysis. An empty cell means the group had no usable value — the condition the vendor sheet reports as a division by zero.

Sample Comparison

Two named samples placed side by side across all analyses, for inspecting outliers.

Trend

The Summary table ordered along the Order axis, so a chronological, dose or time-course series reads in sequence.

Statistics

The same values plotted against the Order axis with error bars. Order defaults to the first number found in the sample name; editing a value and pressing Apply rescales the graph and reorders the Trend sheet, as in the vendor software.

Genotyping and Hardy-Weinberg

Endpoint, melting-curve and gene-scanning genotype calls, with the score and group name where the module records them. The Group names table applies Roche's documented defaults (wild type = AA, heterozygous = AB, mutant/variant = BB), accepts explicit genotypes or two-allele base combinations, and leaves arbitrary numeric groups unassigned. Once AA, AB and BB are identified, allele frequencies are computed from the observed counts, expected counts under equilibrium are derived from those frequencies, and a chi-square statistic with one degree of freedom is tested against the 3.84 critical value at alpha 0.05. A quantification-only experiment carries these properties unset, and the sheet says so.

Runs and QC

The per-run acceptance decision with every check listed, the provenance timeline, and any disagreement between the instrument's sample type and the name-derived role. Per-run exports for LinRegPCR and qpcR are at the bottom of each card.

Plate map

The plate as stored, at whatever geometry the block type declares. Colour it by subset membership, instrument sample type, resolved role, replicate group or stored crossing point. Hover a well for its full record.

Curves

Raw fluorescence from the acquisition store, coloured by stored call or by role, on a linear or log scale.

Per-well results

Every stored result row together with the plate-model fields the vendor result sheet does not expose: instrument sample type, replicate group, subset membership, filter combination, declared and calculated concentration, and the crossing-point state flags.

Instrument records — what the file stores that a result table does not show

The plate model inside the file is considerably richer than the exported results, and several of these fields change how a result should be read.

The sample type records, per well and per detection channel, whether the instrument regarded that reaction as an unknown, a standard, a calibrator or a control — an assignment made at setup and independent of the sample name. Comparing it against the name-derived classification is a genuine control.

The replicate group is the instrument's own pairing rather than a guess from a name suffix. The replicate statistics object holds the mean and standard deviation the instrument itself computed for each group, which the Summary sheet shows beside the recomputed values so that any discrepancy is visible rather than assumed away.

The standard curve object carries the fit method, curve type, slope, intercept, efficiency and validity state. The declared concentration of each standard is what makes an independent refit possible.

The thermal protocol, block type and detection format give the cycling programme, ramp rates, acquisition mode, reaction volume, plate geometry and the excitation and emission wavelengths that define each filter combination — what the vendor Overview sheet reports as the filter combination column. Subsets define exactly which wells belong to which assay, removing any need to infer target membership from position. The plate barcode, the technician recorded with the run and the instrument calibration date are all present and are carried into the report.

Exports and the evidence bundle

Every sheet exports as CSV and every chart as PNG. Each run exports as RDML and as a tidy table, together with a baseline-subtracted curve table and a ready-to-run qpcR script, so an independent curve analysis can be repeated on your own installation.

The evidence bundle is a stored ZIP containing the CSV exports, the chart images, the profile actually used and a README describing the conventions in force. The evidence report embeds the same charts, lists every acceptance check and forensic event, and ends with a signature block; print it to PDF for the record.

One practical note: qpcR does not subtract a baseline by default. Run on raw LightCycler fluorescence, whose plateau-to-baseline ratio is small, it returns efficiencies far below the true value. Always supply the baseline-subtracted table.

Regular expressions in one paragraph

Patterns are case-insensitive. NTC matches any name containing NTC. ^ anchors to the start and $ to the end, so ^GAPDH$ matches only exactly GAPDH. | means or, as in GAPDH|ACTB. \b marks a word boundary, so \bNC\b matches NC PLATE but not NCAM. ? makes the preceding character optional, as in T-?NOS for both T-NOS and TNOS. . is any character and .* is anything at all, so .* as a target pattern applies a rule to every target. Round brackets group alternatives, as in ^(GOI1|GOI2)$.

Limits

Colour compensation is not applied — the fluorescence is read as stored, and a colour-compensated analysis will show compensated results but uncompensated curves. Melting and gene-scanning difference plots are not redrawn; their stored temperatures, peaks and genotype calls are reported. The temperature log is present under a vendor compression that is not part of the published specification and is reported but not decoded. Concentrations are shown as stored, and labelled as relative where the standard-curve state indicates no fitted calibration.

The page reads the archived experiment container. It is not a substitute for the instrument software and does not write back to it, and a call it computes is a reading of the stored data, not an authorisation to report a result.
