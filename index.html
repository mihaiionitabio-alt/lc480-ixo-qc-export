About and methods

The analyzer reads the vendor's stored CrossingPoint and Call; it never estimates or replaces Cq. Raw fluorescence is decoded from AcquisitionStore (Base64 - zlib - inner XML - little-endian float32). The browser efficiency value is the original thesis window-of-linearity (WoL) index with the documented gates R2 >= 0.98 and 30% < E < 140%. Exact LinRegPCR remains the RDML-Python/desktop reference; exact qpcR remains the R l4 + sliwin reference. The report contains signature fields and cryptographic evidence fingerprints, but the printed PDF is not itself a qualified electronic signature.

Target-specific QC acceptance rules — instructions

How the two tables work: sample name → assigned role → target name → expected stored result. For example, CN PORUMB is classified as Negative; its HMG target must amplify at stored Cq 20–27, while its 35S and T-NOS targets must stay clean.

Target-name pattern / regex is matched only against the assay/target name stored in the IXO. Enter targets here (for example HMG, LEC, 35S or T-NOS), not sample/control names such as CN PORUMB or NTC. Matching is case-insensitive.

  • ^HMG$ — exactly HMG.
  • ^(HMG|LEC)$ — exactly HMG or LEC; | means OR.
  • ^(35S|T-?NOS)$ — 35S, TNOS or T-NOS; ? makes the hyphen optional.
  • ^IPC$ — exactly IPC, useful for one named internal control target.
  • .* — every target. Use this for NTC/blank rules only when every channel must stay clean.

^ means start, $ means end, parentheses group alternatives, and .* is a wildcard for any target name.

Theoretical background and methods

This section restates the thesis-level theory behind every quantity the analyzer reports. Cite the thesis (Chapter references) when reproducing any of these arguments in a report or SOP.

1. The .ixo format and the decoding pipeline

A LightCycler 480 .ixo result file is a single XML document whose root is <objectstream>. The structural layer is human-readable UTF-8 XML; binary data appear only inside specific leaf elements, always wrapped in a text-safe encoding (Chapter V.1). The file therefore yields to a two-stage read — recover the XML, then decode the encoded leaves — rather than to byte-offset parsing.

Three recurring primitives traverse the whole file: <obj class="ClassName"> for typed objects, <prop name="PropName">value</prop> for scalar fields, and <list name="ListName"> for ordered collections. The same three primitives recur at every level, so a single generic reader traverses the whole file (Chapter V.1, Listing V.1).

The raw fluorescence — the primary datum whose loss would make the run unreproducible — is not stored as XML in the outer document. It is held in a single property, the AcquisitionStore, as a compressed, doubly-encoded blob. Decoding it proceeds in three stages: Base64 text → a zlib/DEFLATE stream (header 0x78 0x9C) → an inner XML document. The inner XML is itself an object graph: a list of cycles, each holding a list of per-channel acquisitions, each carrying a FloPoints property (Chapter V.6, Listing V.3).

2. Per-well results: crossing points and calls

The quantitative result for every well is stored as an object of class QuantSampleB inside the analysis sample list (Chapter V.5, Table V.3). The crossing point (Cp) is the LightCycler's name for the quantification cycle (Cq); a stored value of 0.0 denotes "no crossing" and must be treated as non-amplification, not as a cycle-zero crossing. Call codes are: 0 = Negative, 1 = Uncertain, 2 = Positive, 3 = NotCalculated.

Alongside CrossingPoint the vendor stores quality fields: CpUncertain (boolean), CpState (descriptor), IsIncluded flag, and optional WarnCodes. Propagating these flags through to the final screening decision turns a bare DETECTED/NOT-DETECTED boolean into a call that carries its own confidence (Chapter XI.2).

3. Amplification efficiency: the window-of-linearity estimator

In the exponential phase a curve follows Fc = F0(1 + E)c, so log10(Fc − β) is linear in cycle c with slope log10(1 + E), where β is the fluorescence baseline. The estimator therefore (i) grid-searches the baseline β just below the observed curve minimum, (ii) selects the window of linearity — the contiguous run of cycles whose baseline-subtracted signal lies between 2% and 25% of the curve amplitude, i.e. above the noise floor and below the plateau shoulder, (iii) fits log10(Fc − β) against c by least squares, keeping the baseline/window combination with the highest R2 (rejecting fits with R2 < 0.98), and (iv) reports

E = (10slope − 1) × 100 %

so that a perfect per-cycle doubling gives slope = log10 2 and E = 100 % (Chapter XII.1, Equation XII.1). The estimator is applied only to wells the instrument called Positive, using the raw fluorescence recovered from the AcquisitionStore; non-amplifying wells have no exponential phase and are skipped. The browser implementation follows this estimator exactly, with the documented gates R2 ≥ 0.98 and 30% < E < 140%.

4. Two quantities called "efficiency"

Assay efficiency (from a dilution series). The MIQE-grade quantity is the amplicon or assay efficiency, obtained from a standard/dilution curve of a known template across several concentrations: E = 10−1/slope − 1, where "slope" is the slope of Cq plotted against log10 of template amount. A perfect doubling per cycle gives slope = −3.32 and E = 100 %; the ENGL acceptance window slope ∈ [−3.6, −3.1] corresponds to E ∈ [89.6%, 110.2%]. This efficiency needs several wells per sample (the dilution points) and is the number a validation report certifies (Chapter XIV.1, Equation XIV.1).

Single-curve efficiency (from one reaction). The quantity the analyzer recovers is different: it is the per-reaction efficiency read from the shape of one amplification curve. In the exponential phase Fc = F0(1 + E)c, so log10(Fc − β) is linear in cycle c with slope log10(1 + E); fitting that slope over the window of linearity returns E for a single well (Ramakers et al., 2003; Ruijter et al., 2009, 2013). Crucially, this needs neither a dilution series nor a spike-in — it is a property of the curve itself. The price of that convenience is interpretive: a single-curve slope on raw, uncalibrated fluorescence is biased and noisier than the dilution-series value; it is best read as a relative kinetic index, reproducible enough to compare like with like but not a substitute for the dilution-series efficiency (Chapter XIV.1).

5. Inhibition: what it is and how it is detected

PCR inhibitors — co-extracted polysaccharides, polyphenols, humic acids, EDTA, residual ethanol and the like — "affect the efficiency of target DNA amplification by interacting with the DNA template, by interfering with the DNA polymerase activity or decreasing the efficiency of enzymatic cofactors (Mg2+)" (Hougs et al., 2019). Inhibition is therefore, by definition, an efficiency phenomenon, and it leaves three fingerprints on the amplification curve: (i) a delayed onset (higher Cq), (ii) a shallower exponential slope — i.e. a lower per-reaction efficiency — and often (iii) a depressed plateau (Chapter XIV.2).

The ENGL/EURL dilution inhibition test is the method-verification standard for GMO laboratories. The working-concentration extract is taken as "undiluted" and a four-fold series is prepared (1:4, 1:16, 1:64, 1:256, in duplicate). The Cq of each dilution is plotted against log(dilution factor) and fitted by linear regression. An extract is accepted as inhibitor-free only if all three conditions hold: (1) the slope lies between −3.6 and −3.1 (equivalently E ∈ [90%, 110%]); (2) R2 ≥ 0.98; and (3) the difference between the measured undiluted Cq and the Cq extrapolated from the dilution line is ΔCq < 0.5 cycle (Chapter XIV.3).

The routine screening plate controls inhibition through two safeguards: (1) the endogenous reference target (HMG/LEC) is the routine inhibition monitor — a delayed reference Cq or a depressed reference efficiency flags the extract on the very plate that produced it; and (2) per-well efficiency as a retrospective screen — any reaction whose single-curve efficiency falls more than two robust standard deviations below its target's median is flagged as a candidate for the confirmatory dilution test (Chapter XIV.4–6).

6. Cross-validation: LinRegPCR, qpcR and the instrument

Because the recovered curves can be written out as tidy tables and as RDML, they can be fed unchanged to the two reference implementations of curve analysis — LinRegPCR (Untergasser et al., 2021), run through the RDML-Python library, and qpcR (Ritz and Spiess, 2008), whose four-parameter log-logistic fit yields both a second-derivative-maximum Cq and a per-curve efficiency (Chapter XII.4).

On the crossing point the three methods and the instrument agree very closely: LinRegPCR and qpcR each track the instrument's second-derivative-maximum Cp with a standard deviation of the difference below 0.2 cycle. On efficiency the three window-of-linearity implementations converge once the baseline is handled consistently: WoL, LinRegPCR and qpcR give 71/75/72% for 35S, 75/86/81% for HMG and (LinRegPCR/qpcR) 101/97% for T-nos — agreement to within a few percentage points at R2 ≈ 1.0. This convergence corroborates both faithful curve recovery and reproducible, order-preserving efficiency (Chapter XII.4).

7. QC rules, sample roles and the acceptance framework

Sample roles are assigned by the first non-empty regular expression that matches the sample name; unmatched samples remain Sample. This is a post-processing classification rather than a vendor field, keeping the plate model general across laboratories (Chapter V.3).

Target-specific acceptance rules then decide, for each assigned role, whether that target must amplify in a stored Cq interval or must stay clean. The rule table is evaluated independently of the sample classification: a well is first classified by its sample name, then each QC rule matching both that role and the well's target is applied. A required rule that finds no matching wells is reported as missing evidence; a matching well that fails the expectation is a QC failure (Chapter X.2).

Replicate agreement is checked by grouping wells that share the same root sample name and target. If all replicates are Positive, their stored Cq spread must not exceed the configured maximum; if all are Negative, they are consistent; mixed calls are a discordant-replicate failure.

8. Provenance, integrity and the evidence bundle

Every input file is SHA-256 hashed at load time; ZIP entries have their CRC-32 verified against the stored value. The evidence bundle contains: source inputs, decoded IXO files, SHA-256 checksums, graph PNGs, CSV exports, RDES and RDML files for LinRegPCR, a qpcR-ready R script, the report HTML, and a manifest with cryptographic fingerprints. The printed/saved PDF is signature-ready but is not itself a qualified electronic signature unless signed with an approved external system (Chapter X.3).
